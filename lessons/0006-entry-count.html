统计进入次数

让已有 HUD 同时显示区域状态和进入次数。每次进入加一，停留不增加，离开保留次数，重新运行归零。

第六课 · 约 10 分钟Godot 4.7.2 · GDScript状态：已完成（2026-09-15 用户确认）
本课只做一个成果

为本次运行增加一个可见的进入计数器。继续使用 World、Trigger 和 HUD/StatusLabel。游戏修改由你动手完成。

1. 核对第五课起点

前五课已确认完成。你已理解 text 保留上次赋值。现在增加一份离开区域后仍有用的数据：这次运行已经进入过几次。

  1. 继续打开已完成第五课的 godot-learning/project.godot。本机保存项目在 /Users/sid/Documents/ChatGPT/Godot/godot-learning。
  2. 先按 F8（Stop，停止） 停止游戏；Mac 功能键被占用时按 Fn+F8。左下 FileSystem（文件系统）→ res:// → world.tscn，双击打开。
  3. 在左上 Scene（场景） 选中 World。展开 HUD，确认其下有 StatusLabel。Player、Wall、Trigger 仍是 World 的直接子节点。
  4. 在 FileSystem 双击 world.gd，中央切到 Script（脚本）。确认已有 $HUD/StatusLabel 引用，进入和离开回调分别更新“区域内”和“区域外”。

检查点：先找到这两处 text 赋值。稍后替换它们，不要在旧赋值后叠加一套显示逻辑。

2. 次数属于 World，文字只是显示

开始运行 区域外 · 进入次数：0 第一次进入 区域内 · 进入次数：1 停留两秒 区域内 · 进入次数：1 完全离开 区域外 · 进入次数：1 再次进入 区域内 · 进入次数：2 停止后重新运行 区域外 · 进入次数：0

entry_count 是 World 脚本的实例字段；Label.text 是由它生成的显示内容。不要从 Label 的字符串中拆出数字再加一。这样以后改提示文案，也不会破坏计数。

Java：实例字段保存计数
根据字段值生成界面文字
→
Godot：World 保存 entry_count
信号回调更新数据与 Label

计数只发生在 body_entered 的 Player 分支里。停留不是新的进入；退出也不是进入。World 统筹区域规则，Player 继续只负责移动。

3. 添加字段与初始显示

在中央 Script 编辑区确认打开的是 world.gd。在 extends Node2D 下方、已有 @onready 声明之前，顶格新增：

var entry_count: int = 0

这是每个 World 实例自己的运行数据，不需要 @export，也不需要 @onready。它初始化为数字 0，不依赖子节点。

找到已有 _ready()。在两个信号连接之后新增下面一行，缩进一个 Tab：

status_label.text = "区域外 · 进入次数：%d" % entry_count

这里使用 @onready 已取得的 Label 引用，在游戏开始时显示 0。出生点仍在区域外；本课保留现有位置。无需修改 Inspector 中的初始 Text，运行时这行会更新它。

%d 表示十进制整数，右侧的 % entry_count 把数值填进去。类似 Java 的 String.format("进入次数：%d", count)。参见 官方 GDScript 格式字符串。

4. 进入加一，离开保留

  1. 找到 _on_trigger_body_entered。在 if body == player: 内第一行新增 entry_count += 1，缩进两个 Tab。
  2. 在同一分支中，把原来的 status_label.text = "区域内" 替换为下面第一行。先加一，再生成文字，避免显示落后一次。
  3. 找到 _on_trigger_body_exited，把原来的 status_label.text = "区域外" 替换为下面第二行，仍在 Player 条件内。离开时不增减 entry_count。
status_label.text = "区域内 · 进入次数：%d" % entry_count
status_label.text = "区域外 · 进入次数：%d" % entry_count

上面两行分别放在两个回调中，不要连续放进同一个回调。已有的颜色赋值、恢复原色、print 和信号连接保持有效。无需新增节点、资源或信号连接。

动手后展开：完整 world.gd 核对版 
extends Node2D

var entry_count: int = 0

@onready var player: CharacterBody2D = $Player
@onready var trigger: Area2D = $Trigger
@onready var original_modulate: Color = player.modulate
@onready var status_label: Label = $HUD/StatusLabel

func _ready() -> void:
	trigger.body_entered.connect(_on_trigger_body_entered)
	trigger.body_exited.connect(_on_trigger_body_exited)
	status_label.text = "区域外 · 进入次数：%d" % entry_count

func _on_trigger_body_entered(body: Node2D) -> void:
	if body == player:
		entry_count += 1
		print("角色进入触发区域")
		player.modulate = Color(1.0, 0.45, 0.45, 1.0)
		status_label.text = "区域内 · 进入次数：%d" % entry_count

func _on_trigger_body_exited(body: Node2D) -> void:
	if body == player:
		player.modulate = original_modulate
		print("角色离开触发区域")
		status_label.text = "区域外 · 进入次数：%d" % entry_count

5. 验证两次进入和一次重新运行

  1. 在 world.gd 代码区按 ⌘S 保存（Windows/Linux 用 Ctrl+S），确认没有红色语法错误。点击顶部 world 场景标签，按 F6（Run Current Scene，运行当前场景），必要时 Fn+F6。
  2. 点击游戏画面取得键盘焦点。左上角应显示 区域外 · 进入次数：0，图标原色。
  3. 短按 W 靠近上方区域，每次约 0.1 秒。图标变色时松开：显示 区域内 · 进入次数：1。停留两秒，次数仍是 1。
  4. 按 S 回到出生点附近，直到碰撞形状完全离开：图标恢复原色，显示 区域外 · 进入次数：1。
  5. 再按 W 进入：次数变成 2。退回出生点，次数仍是 2。
  6. 按 D 撞墙，确认停住；保持 D 短按 W，确认仍沿墙向上滑动。松开按键后停止。碰撞规则应与之前一致。
  7. 按 F8 停止，再保持 world 场景按 F6 重新运行。应回到出生点，显示 区域外 · 进入次数：0。再次进入应显示 1。
  8. 最后按 F8。编辑器底部 Output（输出） 查看进入和离开日志；点击 Debugger（调试器）→ Errors（错误），确认本次运行无新增错误。

重新运行会创建新的 World 实例，字段重新初始化。本课没有把 entry_count 写入文件，所以它只保留在当前运行中。这与“回调结束后属性仍保留”不矛盾：两者讨论的是不同的生命周期边界。

验收链：0 → 进入 1 → 停留 1 → 离开 1 → 再进入 2 → 重开 0。文字与颜色同步，墙仍阻挡。

6. 按现象定位问题

每次进入都显示 1

确认 entry_count 声明在函数外。如果在进入回调内写 var entry_count = 0，每次调用都会新建局部变量；也不要在回调里把实例字段归零。

停留时次数持续增加

检查自增是否误放进 _process 或 _physics_process。它应只在 World 的 body_entered 接收方法、Player 条件内执行。

进入后次数总落后一次

检查执行顺序：先 entry_count += 1，再生成 text。Label 不会自动跟踪字段；后续只改数字，不重新赋值 text，屏幕不会自动更新。

离开时次数归零或增加

离开回调只读取次数生成文字。删除误加的归零或自增语句。若中心退出但没有退出日志，先让整个碰撞圆离开区域。

仍只有区域内／区域外，没有次数

确认编辑并保存的是运行项目里的 world.gd。找到两处旧 text 赋值，按第 4 节替换；不要让旧赋值覆盖新文字。确认运行 world 场景。
