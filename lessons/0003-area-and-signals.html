第二课

进入区域，触发事件

给 World 添加一个可穿过的触发区域。角色进入时输出提示，停留时不重复输出，离开后再进入会再次输出。

第三课 · 约 20 分钟面向有经验的 Java 开发者

1. 从事件监听理解信号

上一课的 StaticBody2D 阻挡角色；本课的 Area2D 检测重叠，不充当实体墙。两者都用 CollisionShape2D 定义边界。引擎发现角色进入区域后，Area2D 发出 body_entered 信号，已连接的方法接收进入者。

Java：注册事件监听器
addListener(this::onEntered)
→
Godot：连接信号
body_entered.connect(handler)

这是观察者模式的类比。信号由 Godot 对象系统提供，不需要自行定义 Listener 接口。默认连接直接调用接收方法，不能据此假定有消息队列、后台线程或异步执行。

本课由 World 连接子节点：区域负责检测，World 决定进入区域意味着什么。Player 的移动脚本无需知道区域的存在。

2. 先找到编辑器里的操作位置

以下按本机 Godot 4.7.2 的英文界面说明，中文名称用于对照。面板可以拖动；如果布局不同，请按面板名称找，不必按屏幕坐标找。

  • 左上 Scene（场景）：显示节点树。这里选节点，也在这里添加子节点。面板左上角的 ＋ 是添加节点入口。
  • 左下 FileSystem（文件系统）：显示项目文件。res:// 就是本仓库的 godot-learning/，不是仓库根目录。
  • 右侧 Inspector（检查器）：修改当前选中对象的属性。每次修改前，先看面板顶部的对象名称。Filter Properties 是属性筛选框；看不到分组时先清空筛选。
  • 顶部中央 2D / Script（脚本）：切换场景画布与代码编辑器。底部 Output（输出）：查看 print() 的内容。
  1. 在左下 FileSystem 展开 res://，双击 world.tscn。顶部场景标签应切换为 world。
  2. 点击顶部中央 2D。左上 Scene 应显示根节点 World，其下有 Player 和 Wall。保留这两个节点。

3. 添加 Trigger 和矩形检测形状

3.1 在 World 下添加 Area2D

  1. 在左上 Scene 中单击 World，再点击该面板左上角的 ＋（Add Node，添加节点）。
  2. 在弹出的创建节点窗口中搜索 Area2D，选中同名类型，点击 Create（创建）。
  3. 在 Scene 中右键新建的 Area2D，选择 Rename（重命名），输入 Trigger，按 Enter。它应与 Player、Wall 同级，而不是放在 Player 下面。
  4. 保持选中 Trigger。在右侧 Inspector 向下找到 Node2D → Transform（变换），点击分组左边的小三角展开。在 Position（位置） 的 x、y 输入框中分别填 180、100，每次输入后按 Enter。Rotation 保持 0，Scale 保持 (1, 1)。

检查点：Scene 中出现 World 的直接子节点 Trigger。此时旁边可能有黄色警告，表示还没有检测形状；完成下一步后再检查。

3.2 创建 Shape 资源，再修改 Size

  1. 在左上 Scene 选中 Trigger，点击 ＋，搜索 CollisionShape2D，点击 Create。保留默认名称，并确认它缩进在 Trigger 下面。
  2. 选中这个新建的 CollisionShape2D。右侧 Inspector 顶部 CollisionShape2D 分组里有一行 Shape（形状），右侧目前显示 <empty>。
  3. 点击 Shape 值框最右侧的下拉箭头，选择 New RectangleShape2D（新建 RectangleShape2D）。这一步创建的是资源，不是在场景树里再添加节点。
  4. 创建后，点击 Shape 行里的 RectangleShape2D 资源名称，展开内嵌属性。在出现的 Size（尺寸） 中把 x 设为 120、y 设为 60。这是矩形的完整宽高，不是半宽半高。
  5. 仍选中这个 CollisionShape2D，确认 Disabled（禁用） 复选框未勾选。向下展开 Node2D → Transform → Position，保持 (0, 0)；Scale 保持 (1, 1)。它的位置是相对 Trigger 的，不要再填 (180, 100)。

找不到 Size？先确认选中的是 Trigger 下的 CollisionShape2D，再点 Shape 中的资源名称展开。Size 属于 RectangleShape2D 资源，不在 Node2D 的 Transform 分组里。

World (Node2D) ├── Player (CharacterBody2D) ├── Wall (StaticBody2D) └── Trigger (Area2D) └── CollisionShape2D

3.3 设置谁检测谁

  1. 回到左上 Scene，重新选中 Trigger。右侧 Inspector 的 Area2D 分组中找到 Monitoring（监测），保持勾选。这是“主动检测进入者”的开关；不要把旁边的 Monitorable 当成同一个属性。
  2. 在 Inspector 向下找到 CollisionObject2D → Collision（碰撞），点击小三角展开。里面分别有 Layer（层） 与 Mask（掩码） 的数字格子。
  3. 在 Layer 行取消所有已选中的层；在 Mask 行只保留数字 1 选中。数字格子是开关，点击会切换状态；不要在已经选中的 1 上再点一次。
  4. 在 Scene 选中 Player，到右侧 CollisionObject2D → Collision → Layer，确认第 1 层选中。Player 上方还有 CharacterBody2D 自己的 Collision 分组；这里要找的是 CollisionObject2D 下的 Collision。保留 Player 的 Mask。

Layer 表示“我在哪些层”，Mask 表示“我要检测哪些层”。这里由 Trigger 的 Mask 匹配 Player 的 Layer。Trigger 自己可以不占任何层；Player 也不需要为了这个检测修改 Mask。Wall 同样在第 1 层，所以接收方法还会识别具体进入者。

你当前 Player 位于约 (163, 283)，圆形碰撞半径约 87.3。这个区域在出生点上方，初始不会重叠。按 W 接近它即可；当碰撞形状重叠时就会触发，不必等角色中心进入。

4. 给 World 挂脚本并连接信号

当前仓库已有 world.gd 模板文件，但 world.tscn 的 World 尚未挂载它。按下面步骤复用这个文件。

  1. 在左下 FileSystem → res:// 找到 world.gd，把它拖到左上 Scene → World 根节点上再松开。不要拖到 Player 或 Wall。如果 World 旁边已有脚本图标，先点击图标确认已挂载的文件；已经是 world.gd 就跳过拖动。
  2. 确认 World 右侧出现脚本图标。选中 World，在右侧 Inspector 底部的 Script（脚本） 属性也应能看到 world.gd。
  3. 双击 FileSystem 中的 world.gd，中央切到 Script 编辑器。确认正在编辑 world.gd，将现有模板内容全部替换为下方代码。函数体用 Tab 缩进。
  4. 保存脚本：macOS 按 ⌘S，Windows/Linux 按 Ctrl+S。再点击顶部 world 场景标签，使用 Scene（场景）→ Save Scene（保存场景） 保存节点和脚本挂载关系。macOS 的 Scene 菜单位于屏幕顶部系统菜单栏。

本课通过代码连接信号。右侧 Signals（信号） 标签是编辑器连接入口，本课无需操作它，也无需再生成一个回调。

extends Node2D

@onready var player: CharacterBody2D = $Player
@onready var trigger: Area2D = $Trigger

func _ready() -> void:
	trigger.body_entered.connect(_on_trigger_body_entered)

func _on_trigger_body_entered(body: Node2D) -> void:
	if body == player:
		print("角色进入触发区域")

$Player 是相对当前节点的 get_node("Player") 简写。它依赖场景中的节点路径和名称，不是 Java 字段自动注入。

@onready 把引用初始化推迟到节点准备就绪时，在本节点的 _ready() 前执行。World 的子节点会先完成各自的 ready 阶段，然后 World 执行 _ready()，此时连接子节点信号。把它理解为场景生命周期中的初始化回调，比把它当 Java 构造器更准确。

connect() 接收方法对应的 Callable。传入方法名，不加调用括号。body 是信号携带的实际进入者；body == player 判断是否为这个 Player 实例，不靠节点名称猜测身份。

事件链：物理步检测到重叠开始 → Trigger 发出 body_entered → World 的接收方法执行 → 确认进入者 → 输出提示。无需在 Player 的每帧回调中轮询区域。

5. 显示检测形状并运行验证

CollisionShape2D 本身不会作为游戏美术显示。运行前开启 Debug（调试）→ Visible Collision Shapes（显示碰撞形状），才能看到检测区域。这个入口属于编辑器的运行调试选项，不在 Inspector 中。部分版本将 Debug 放在顶部菜单栏；macOS 还需查看屏幕顶部系统菜单栏。若当前布局找不到该项，可用下面的命令直接以碰撞可视化模式运行同一项目。

找不到 Debug 菜单：本机终端运行方式

打开 macOS 的“终端”，执行以下命令。运行后在游戏窗口按键，提示会显示在这个终端中。此方式不用寻找 Debug 菜单。

/Applications/Godot.app/Contents/MacOS/Godot --path /Users/sid/Documents/ChatGPT/Godot/godot-learning --debug-collisions
  1. 先保存，确认顶部当前场景标签是 world，按 F6（Run Current Scene，运行当前场景），Mac 功能键被系统占用时按 Fn+F6。也可将鼠标悬停在编辑器右上角的运行图标上，找到提示为 Run Current Scene 的按钮再点击。
  2. 点击游戏画面让它获得键盘焦点。在编辑器底部点击 Output（输出） 标签展开日志；不是右侧 Inspector，也不是 Debugger 的错误列表。使用上方终端命令运行时则看终端输出。
  3. 按 W 接近上方区域。出现“角色进入触发区域”，角色仍能继续穿过。
  4. 在形状重叠时松开按键，等两秒。输出不应继续增加。
  5. 按 S 回到出生点，确保碰撞形状完全离开，再按 W 进入。提示应新增一次。
  6. 再次向右撞墙，确认第二课的墙仍会阻挡角色。验证完点击编辑器右上角的方形 Stop（停止） 按钮；若通过终端启动，关闭游戏窗口即可。
按现象排查
  • 提示找不到节点：脚本应挂在 World，Player 和 Trigger 应为它的直接子节点，名称大小写一致。
  • 能穿过但没有输出：检查 Trigger 的 Monitoring、Mask 第 1 层、Player 的 Layer 第 1 层，以及双方 Shape 是否有效。确认运行的是 World。
  • 回调选择错误：CharacterBody2D 对应 body_entered；area_entered 用于另一个 Area2D。
  • 停留不再输出：这是预期行为。body_entered 表示“开始重叠”，不是“每个物理步仍在重叠”。
