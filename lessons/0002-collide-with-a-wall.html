让墙挡住角色

给已运行的八方向移动 Demo 加一面墙：正面撞上会停住，斜着撞上会沿墙滑动。

第二课 · 约 10 分钟Godot 4 · GDScript

先预测，再动手

不看脚本：同样的 Speed，同时按 W 和 D 会比只按 D 快约 41%。

1. 四个角色，各管一件事

World (Node2D) ├── Player (CharacterBody2D) ← 执行角色移动 │ ├── Sprite2D ← 显示图标 │ └── CollisionShape2D ← 角色的碰撞轮廓 └── Wall (StaticBody2D) ← 静态障碍物 └── CollisionShape2D ← 墙的碰撞轮廓

CharacterBody2D 提供角色移动接口；StaticBody2D 适合这面不动的墙。CollisionShape2D 把形状提供给直接父级碰撞对象。形状描述“边界在哪里”，身体决定“如何参与碰撞”。参见 StaticBody2D 与 CollisionShape2D。

move_and_slide() 使用 velocity 移动角色，并处理碰撞。正面没有可走的方向就停住；斜着碰到平直墙面时可以沿墙移动。不要改成直接写 position。官方教程：移动与碰撞。

2. 在现有项目中搭一面墙

打开已有的 godot-learning/project.godot。保留第一课的 player.tscn 与输入动作。

  1. 新建场景，根节点选 Node2D，命名为 World，保存为 world.tscn。
  2. 把文件系统面板里的 player.tscn 拖到 World 下，创建场景实例。选中这个 Player，把 Transform → Position 设为 (180, 300)。
  3. 仍选中 Player，把 Motion Mode 改为 Floating。这是俯视移动：不区分地板与天花板，碰撞都按墙处理。参见 官方移动模式说明。
  4. 选中 World，添加 StaticBody2D，命名为 Wall。Position 设为 (500, 300)。Wall 与 Player 必须同级。
  5. 给 Wall 添加直接子节点 CollisionShape2D。在 Shape 新建 RectangleShape2D，展开资源，把 Size 设为 (40, 500)。子节点 Position 保持 (0, 0)，Scale 保持 (1, 1)。
  6. 确认 Player 原有的 Shape 不为空。两边的 Disabled 都关闭。Player 与 Wall 的 Collision → Layer / Mask 都只勾选第 1 层，便于本课验证。

这面墙没有美术节点。运行前开启编辑器的 Debug → Visible Collision Shapes（显示碰撞形状）。形状平时不作为游戏画面显示；调试视图用来观察真实边界。

3. 移动代码保持这条流水线

第一课脚本已经足够。核对下面两行仍在 _physics_process() 中，且顺序一致：

velocity = direction * speed
move_and_slide()

velocity 的单位是像素/秒，不要再乘 delta。move_and_slide() 内部处理物理步长，也可能因碰撞修改速度；每个物理步再按输入设置速度。参见 velocity 与 move_and_slide()。

4. 运行，立刻看结果

保存 World，点击运行当前场景（F6；部分 Mac 键盘需 Fn）。这次必须运行 World。F5 可能仍会运行第一课的 Player。

  1. 按住 D：角色向右撞到墙的左侧，应停住。碰撞轮廓不能穿墙。
  2. 保持 D，再按 W 约半秒：角色应沿墙向上滑动。不要一直按到墙顶；离开墙的端点后可以绕过去。
  3. 松开全部按键：角色应立即停止。重新运行当前场景可回到起点。
结果不对？按现象检查
  • 没有墙：先检查运行的是 World，以及“显示碰撞形状”是否开启。
  • 穿墙：检查两边的 Shape、Disabled 和 Layer / Mask，再确认调用了 move_and_slide()。
  • 墙跟着角色走：Wall 应挂在 World 下，不能挂在 Player 下。
  • 图标还没碰墙就停了：对照调试轮廓。你当前圆形半径约 87.3，比图标边缘更宽；这是形状决定碰撞的直接证据。
