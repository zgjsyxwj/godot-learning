进入三次，达成目标

把计数器变成一个小目标：第三次进入时显示“目标达成！”，离开和第四次进入后仍保留提示。

第七课 · 约 10 分钟Godot 4.7.2 · GDScript状态：已完成（2026-09-15 用户确认）
本课只做一个成果

在已有 HUD 增加目标是否达成的提示。继续自由移动和累计次数；停止后重新运行，次数归零、目标重新开始。游戏代码由你动手修改。

1. 核对起点

  1. 打开 godot-learning/project.godot。按 F8（Stop，停止） 停止游戏；Mac 功能键被占用时用 Fn+F8。
  2. 左下 FileSystem（文件系统）→ res:// → world.tscn，双击打开。左上 Scene（场景） 中确认 World 下有 Player、Trigger 和 HUD，HUD 下有 StatusLabel。
  3. FileSystem 中双击 world.gd，中央进入 Script（脚本） 编辑区。本课只编辑这个脚本。
  4. 你当前代码在两个回调中都保留了一行旧赋值：status_label.text = "区域内" 或 "区域外"。它们立即被带次数的新赋值覆盖。先删除这两行旧赋值。

2. 完成状态由次数决定

次数 0、1、2 → 目标未达成 次数 3、4、5… → 目标达成！ 停止后重新运行 → 次数 0 → 目标未达成

使用 entry_count >= 3，而不是 == 3。后者在第四次进入时会变成 false。本课次数只增加，因此不必再保存一个完成布尔字段：每次显示时都可以从次数算出结果。

“目标已达成”是当前状态。它与“刚刚达成时发一次奖励”不同；本课只显示状态，不增加奖励事件。

3. 写一个统一更新 HUD 的函数

在 world.gd 的 extends Node2D 下方、var entry_count 上方，顶格新增目标常量：

const TARGET_ENTRIES: int = 3

它类似 Java 的常量，表示本课固定规则。再到脚本末尾，顶格新增下面的函数。函数体缩进一个 Tab，if 内再缩进一个 Tab：

func _update_status(area_status: String) -> void:
	var goal_status: String = "目标未达成"
	if entry_count >= TARGET_ENTRIES:
		goal_status = "目标达成！"
	status_label.text = "%s · 进入次数：%d · %s" % [area_status, entry_count, goal_status]

_update_status 是我们自己定义的普通方法，不是引擎回调。名字以下划线开头不会使它自动执行；后面要主动调用它。

area_status 接收调用方传来的“区域内”或“区域外”。局部变量 goal_status 每次重新计算显示文案，不负责累计次数。entry_count 仍由 World 实例保存。

格式字符串里的三个占位符与右侧数组按顺序对应：%s 区域文字、%d 次数、%s 目标文字。参见 官方文档：多个占位符。

4. 在三个位置调用它

  1. 在 _ready() 中，将原来的整行 status_label.text = ... 替换为 _update_status("区域外")。保留前面的两条信号连接。
  2. 在 _on_trigger_body_entered 的 Player 分支中，将文字赋值替换为 _update_status("区域内")。它必须位于 entry_count += 1 之后。保留日志和变色。
  3. 在 _on_trigger_body_exited 的 Player 分支中，将文字赋值替换为 _update_status("区域外")。保留恢复原色和日志，退出不修改次数。

检查点：整个脚本中只剩一处 status_label.text =，位于新函数中。三个调用点共用同一个显示规则，因此离开时也不会丢失目标提示。

动手后展开：完整 world.gd 核对版
extends Node2D

const TARGET_ENTRIES: int = 3
var entry_count: int = 0

@onready var player: CharacterBody2D = $Player
@onready var trigger: Area2D = $Trigger
@onready var original_modulate: Color = player.modulate
@onready var status_label: Label = $HUD/StatusLabel

func _ready() -> void:
	trigger.body_entered.connect(_on_trigger_body_entered)
	trigger.body_exited.connect(_on_trigger_body_exited)
	_update_status("区域外")

func _on_trigger_body_entered(body: Node2D) -> void:
	if body == player:
		entry_count += 1
		print("角色进入触发区域")
		player.modulate = Color(1.0, 0.45, 0.45, 1.0)
		_update_status("区域内")

func _on_trigger_body_exited(body: Node2D) -> void:
	if body == player:
		player.modulate = original_modulate
		print("角色离开触发区域")
		_update_status("区域外")

func _update_status(area_status: String) -> void:
	var goal_status: String = "目标未达成"
	if entry_count >= TARGET_ENTRIES:
		goal_status = "目标达成！"
	status_label.text = "%s · 进入次数：%d · %s" % [area_status, entry_count, goal_status]

5. 运行并验证边界

  1. 在脚本编辑区按 ⌘S 保存（Windows/Linux 用 Ctrl+S）。确认无红色语法错误。点击顶部 world 场景标签，按 F6（Run Current Scene，运行当前场景），必要时 Fn+F6。
  2. 点击游戏画面取得键盘焦点。初始应显示“区域外 · 进入次数：0 · 目标未达成”。
  3. 短按 W，每次约 0.1 秒，进入上方区域后松开；再按 S，直到整个碰撞圆离开。重复两轮，次数为 2，目标仍未达成。
  4. 第三次进入后松开按键。应显示“区域内 · 进入次数：3 · 目标达成！”。停留两秒，次数仍为 3，图标保持变色。
  5. 完全离开：显示“区域外 · 进入次数：3 · 目标达成！”，图标恢复原色。
  6. 第四次进入：次数为 4，仍显示“目标达成！”。你仍可以移动。
  7. 退回出生点附近，按 D 撞墙确认停住，保持 D 短按 W 确认沿墙滑动；松开按键停止。
  8. 按 F8 停止，再按 F6 运行。确认回到次数 0、目标未达成。最后 F8 停止，在编辑器底部 Debugger（调试器）→ Errors（错误） 检查本次运行无新增错误。
验收链：2 未达成 → 3 达成 → 停留仍为 3 → 离开仍达成 → 4 仍达成 → 重开 0 未达成。

6. 按现象定位问题

第四次进入又显示未达成

检查条件是否误写成 ==。本课要求达到或超过目标，使用 >=。

离开后完成提示消失

检查退出回调是否仍在直接写旧 text；它也需要调用 _update_status。确保调用之后没有旧赋值覆盖结果。

第三次还未完成，第四次才完成

进入回调必须先更新次数，再调用显示函数。也要检查条件是否误写成 >。

新增函数没有执行或找不到函数

确认名称一致，三个位置都主动调用它；函数声明顶格，不要放进其他函数内部。无需连接新信号。
