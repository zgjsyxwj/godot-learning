按 R 重新开始

在游戏中按一次 R，回到出生点，次数归零，目标重新开始。

2. 添加 restart 输入动作

保持 world 场景打开、World 选中。输入映射属于整个项目，无需在 Inspector（检查器）中修改节点属性。

  1. 顶部菜单 Project（项目）→ Project Settings…（项目设置）→ Input Map（输入映射）。
  2. 在顶部 Add New Action（添加新动作） 输入框中输入 restart，点击右侧 Add（添加）。若已经有同名动作，直接检查它的绑定。
  3. 找到 restart 行，点击该行右侧的 ＋（添加事件）。
  4. 在事件配置对话框顶部的按键监听区域点击后，按一下 R。确认识别结果为 R，点击 OK（确定）。
  5. 展开 restart 左侧的小三角，确认下方列出 R。若显示 R (Physical)，表示按键的物理位置；本课使用该绑定即可。点击 Close（关闭） 返回编辑器。项目设置会保存输入映射。

检查点：动作名称必须是小写 restart。只新增动作名称而没有绑定 R，游戏不会收到对应按键动作。

这里复用第一课的输入映射思路：R 是实际按键，restart 是游戏中的意图。以后更换按键，只需修改映射。入口参见 官方文档：输入动作。本机已核对 Project 菜单；事件配置子界面的文字未完成逐项实机核对，若显示不同，以“监听按键 → R → 确认”的操作为准。

3. 接收一次按下事件

回到 FileSystem → world.gd。在脚本末尾顶格新增以下方法。函数体用一个 Tab，if 内用两个 Tab，错误处理内部用三个 Tab。不要放进已有函数内部。

func _unhandled_input(event: InputEvent) -> void:
	if event.is_action_pressed("restart"):
		var error: Error = get_tree().reload_current_scene()
		if error != OK:
			push_error("重新开始失败：%s" % error_string(error))
  • _unhandled_input 是引擎回调。输入事件未被前面的界面等处理时，引擎会调用它。无需自己调用或连接信号。
  • event 是这一次输入事件。event.is_action_pressed("restart") 检查它是否匹配 restart 的按下事件；松开不匹配，默认也忽略长按产生的键盘重复事件。
  • get_tree() 取得管理当前场景的 SceneTree。reload_current_scene() 重新实例化当前场景。
  • error 是本次调用的返回结果。OK 表示成功；否则 push_error 将可读错误写入调试器。它是局部变量。

与 Player 每个物理帧读取移动输入不同，这里处理离散事件。不要把这段改成在 _physics_process 里每帧检查 Input.is_action_pressed；持续按住时那样会反复请求重载。参见 InputEvent.is_action_pressed。

4. 为什么不用逐项归零？

旧 World：次数 3，角色在区域内 ↓ R → restart → 场景重载 新 World：entry_count 初始化为 0 新 Player：恢复场景保存的位置和原色 新 World._ready()：连接信号，更新 HUD ↓ 区域外 · 进入次数：0 · 目标未达成

重载会替换 World 及其场景中的子节点。新实例重新初始化字段，执行 @onready 和 _ready。旧实例上的累计值不被带过去。goal_status 仍然由次数重新计算。参见 SceneTree.reload_current_scene。

只写 entry_count = 0 不会自动恢复 Player 位置、颜色或 Label.text。本课“重新开始”要求整个当前场景回到保存状态，直接重载符合这个语义。项目输入映射仍有效；并非所有游戏数据都会随场景重载清除。

本课沿用出生点在区域外的场景布局。重载后若出生点与 Trigger 重叠，物理检测会再次触发进入，次数可能立刻变成 1。运行中的位置变化不会自动写回场景文件。

5. 运行验收

  1. 在 Script 编辑区按 ⌘S 保存（Windows/Linux 用 Ctrl+S）。点击顶部 world 场景标签，按 F6（Run Current Scene，运行当前场景），必要时 Fn+F6。必须运行 world，不是 player。
  2. 点击游戏画面取得键盘焦点。初始次数 0、区域外、目标未达成，图标为原色。
  3. 短按 W 进入上方区域，松开；按 S 直到碰撞圆完全离开。先确认退出显示“区域外”，次数保留。
  4. 进入三次。第三次停留在区域内，松开移动键，确认次数 3、目标达成、图标变色。
  5. 短按 R 后松开：游戏仍在运行，角色回出生点，恢复原色；显示区域外、次数 0、目标未达成。
  6. 再次进入，确认次数为 1，停留两秒仍为 1；完全离开后为区域外、次数仍为 1。
  7. 在区域外按 R，再次确认归零。然后长按 R 约两秒，保持 R 时短按 D：角色应能持续移动，不会反复被拉回出生点。最后松开所有键。
  8. 检查 WASD 和斜向移动仍有效。向右撞墙确认阻挡，同时按 W 确认沿墙滑动。最后按 F8，打开底部 Debugger（调试器）→ Errors（错误），确认本次无新增脚本错误。
验收链：3 达成、区域内 → R → 出生点、原色、0 未达成 → 再进入 1 → 离开保留 1 → R → 0。

6. 按现象排查

按 R 没反应

按顺序检查：游戏画面是否有焦点 → Project Settings → Input Map 的 restart 是否绑定 R → 脚本字符串是否完全一致 → 新回调是否顶格写在 world.gd → 是否保存并运行 world 场景。

次数归零，但位置或颜色没恢复

检查是否只手动修改了计数。新方法应调用 reload_current_scene。确认保存的 world.tscn 中 Player 出生点位于 Trigger 外。

重开之后立刻变成 1

先松开所有移动键再按 R。若仍出现，检查出生点是否与 Trigger 重叠；碰撞圆半径比图标看起来大。保持原有出生点布局。

长按 R 时反复回到出生点

核对使用的是 event.is_action_pressed，且没有把 allow_echo 参数设为 true。不要另加每帧重载代码。
